# Repository Guidelines

## Current Direction

This project is a Chrome Manifest V3 extension that adds a compact Claude usage indicator into the Claude.ai composer. Keep future work focused on making the overlay accurate, visually native to Claude, and minimally invasive.

The extension should continue to:

- Fetch Claude account usage from Claude's own authenticated browser session when possible.
- Display plan usage in the inline bar and hover panel.
- Display current-chat context/token usage in the circular ring and hover panel.
- Estimate local chat tokens from the actual visible conversation transcript only.
- Store only sanitized usage metadata and local numeric estimates.

When continuing from here, first verify whether the unpacked `dist/` extension has been reloaded in Chrome after manifest or service-worker changes. Permission changes require a reload from `chrome://extensions`.

## Project Structure & Module Organization

This repository is a Chrome Manifest V3 extension built with Vite, TypeScript, React, and CRXJS.

- `src/manifest.ts` defines the generated extension manifest.
- `src/background/` contains the Manifest V3 service worker. It owns authenticated Claude API calls and throttling.
- `src/content/` contains the Claude page content script, inline usage UI, DOM heuristics, and estimator logic.
- `src/popup/` contains the extension popup React app and styles.
- `src/shared/` contains storage helpers, shared constants, TypeScript types, and Claude usage API normalization.
- `src/test/` contains Vitest unit tests and setup.
- `public/` contains static extension assets, including icons and `pageProbe.js`.
- `dist/` is generated by `npm run build` and is the folder loaded in Chrome.

## Important Files To Navigate

- `src/content/content.tsx` mounts the overlay into Claude's real chat composer, refreshes local transcript estimates, listens for page-probe metadata, and asks the background worker to refresh Claude API usage when Claude loads.
- `src/content/ContentApp.tsx` renders the inline horizontal plan-usage bar, the usage hover panel, the circular context/token ring, and the context hover panel.
- `src/content/styles.css` controls all injected overlay styling. Match Claude's UI: `Anthropic Sans`, subdued gray text, Claude-orange usage fills, compact spacing, and pointer hover targets.
- `src/content/claudeDom.ts` reads page DOM metadata and extracts transcript text for token estimation. Keep this strict: it should read message text only, not action buttons, timestamps, hidden duplicate labels, settings textareas, or the extension UI.
- `src/content/usageEstimator.ts` contains simple local token/message estimate helpers.
- `src/background/background.ts` handles `CLAUDE_USAGE_BAR_FETCH_API_USAGE`, fetches org usage through Claude's session cookies, caches the organization id, throttles refreshes, and stores sanitized snapshots.
- `src/shared/claudeUsageApi.ts` extracts the org id and normalizes Claude `/usage` API responses into the project's `RealUsageSnapshot` shape.
- `src/shared/storage.ts` gates all persisted state and rejects unsafe conversation/auth fields for real usage snapshots.
- `src/popup/popup.tsx` displays local/API status and can manually refresh Claude API usage.

## Implemented Behavior And How It Works

### Composer Overlay

The overlay is inserted into Claude's actual chat composer controls, not arbitrary textareas. Avoid broad textarea fallbacks; they can mount into settings fields such as `#conversation-preferences`. The current mounting heuristic finds the composer controls near the "Add files, connectors, and more" button and rejects preference/settings containers.

The inline UI currently consists of:

- A horizontal plan usage bar, with no inline percentage text.
- A hover panel for plan usage with rows for 5-hour, weekly all models, Claude Design, and routines.
- A small circular context ring, colored Claude orange.
- A hover panel for context usage showing percentage and estimated token count.

The usage-page arrow should point to `/settings/usage`.

### Claude Usage API

Use the background service worker for Claude usage data. The useful Claude API shape is:

- `GET https://claude.ai/api/organizations` to determine the active organization UUID.
- `GET https://claude.ai/api/organizations/{org_id}/usage` to fetch usage.
- Fetches must use `credentials: "include"` and `Accept: "application/json"` so Claude's existing browser session cookies authenticate the request.

The known `/usage` response shape includes limit objects:

- `five_hour.utilization` is the 5-hour usage percentage.
- `five_hour.resets_at` is the 5-hour reset timestamp.
- `seven_day.utilization` is weekly all-models usage percentage.
- `seven_day.resets_at` is weekly reset timestamp.
- `seven_day_sonnet` and `seven_day_opus` may be present for model-specific weekly caps.
- Related Claude Design/routines keys may appear by plan or product surface; normalize them only when present.

The worker caches `organizationId` in `chrome.storage.local`, throttles usage refreshes to roughly once per minute, and clears the cached org id if auth/org lookup fails. It detects missing login via absent Claude cookies or `401/403` responses.

Do not persist raw API payloads. Normalize into `RealUsageSnapshot` using `src/shared/claudeUsageApi.ts`, then store only allowlisted fields such as percentages, reset display text, and routines counters.

### Token / Context Estimation

The context ring should be driven by the local token estimator, not the Claude plan usage API. Token estimation should read any chat length and any message content type while counting text only.

`src/content/claudeDom.ts` should:

- Find actual user message containers, e.g. `[data-testid="user-message"]`, `[data-message-author-role="user"]`, `.font-user-message`.
- Find actual Claude response containers, e.g. `.font-claude-response` and assistant message containers.
- Clone each message container.
- Remove controls/chrome from the clone: message action groups, buttons, scripts/styles, hidden `sr-only` duplicates, `aria-hidden` UI, and the extension overlay.
- Read all remaining text once.

This is intended to include real message text from paragraphs, headings, lists, code blocks, tables, SVG diagram labels, and other rendered text inside the message. It should exclude Copy/Edit/Retry buttons, timestamps, feedback controls, hidden accessibility summaries, page chrome, settings textareas, and usage overlay text.

The estimator is approximate, deliberately local, and now uses the Claude tokenizer with a `text.length / 4` fallback only if tokenizer initialization fails. Do not store conversation text; only store numeric estimates in `chatUsage`.

Recent implementation notes:

- `src/shared/claudeTokenizer.ts` now wraps `@huggingface/tokenizers` around the local `Xenova/claude-tokenizer` assets (`src/shared/claude-tokenizer.json` and `src/shared/claude-tokenizer-config.json`).
- `src/content/usageEstimator.ts` and `src/shared/claudeConversationContext.ts` now count visible text with the Claude tokenizer and keep the prior heuristic only as a fallback if tokenizer initialization fails.
- The tokenizer assets are bundled locally so the extension does not fetch model files at runtime.
- Verification passed with `npm test` and `npm run build`.

### DOM Page Probe

`public/pageProbe.js` and `src/pageProbe/pageProbe.ts` intercept same-origin JSON responses in the page world and sanitize usage-like metadata before posting to the content script. Keep this path conservative and allowlist-only. It is a fallback/side channel, not the primary API integration now that the background worker fetches `/usage`.

## Build, Test, and Development Commands

- `npm install` installs dependencies from `package-lock.json`.
- `npm run dev` starts the Vite/CRXJS development server.
- `npm test` runs all Vitest unit tests once.
- `npm run test:watch` runs tests in watch mode.
- `npm run build` typechecks with `tsc --noEmit` and builds the loadable extension into `dist/`.

Load the extension from `dist/`, not the repository root.

## Coding Style & Naming Conventions

Use TypeScript and React function components. Keep modules small and focused by feature area. Prefer named exports for shared helpers and components.

Use two-space indentation, semicolons, and double quotes, matching the existing files. Name React components in `PascalCase` such as `ContentApp`, and helper files/functions in `camelCase` such as `usageEstimator.ts` and `estimateTokensFromText`.

There is no formatter or linter configured yet, so preserve the existing style manually.

## Testing Guidelines

Tests use Vitest with `jsdom`. Place tests under `src/test/` and name files `*.test.ts` or `*.test.tsx`.

Focus tests on privacy-sensitive logic, storage behavior, sanitization, date rollover, API normalization, transcript extraction, and estimator calculations. Run `npm test` before submitting changes. Run `npm run build` after content script, manifest, popup, background, or public asset changes.

## Security & Privacy Notes

The extension may call Claude.ai API endpoints using the user's existing Claude session cookies, but only for usage metadata. Do not call unrelated third-party services. Do not store prompts, responses, cookies, auth headers, request bodies, raw Claude payloads, or conversation text. Any API or page-probe data must be sanitized to allowlisted usage metadata before storage or UI rendering.

Safe persisted data includes:

- settings
- local date/message counters
- numeric estimated token counts
- sanitized usage percentages
- sanitized reset display strings
- sanitized routines counters
- cached Claude organization id

Unsafe persisted data includes raw conversation text, prompt/response bodies, request headers, cookies, auth tokens, raw API responses, uploaded file contents, or unbounded arbitrary JSON.
